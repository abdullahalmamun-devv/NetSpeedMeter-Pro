## Real-data fixture incident and safety response

The old `InstallerFreshInstallUpgradeAndUninstallDrill` used a sandbox install path but called `UninstallAsync(PurgeUserData:true)` without a sandbox data override. That selected the real current-account `%LocalAppData%\SpeedMeterPro`. The directory later contained a 479,232-byte database, logs, crashes and a lock, but no trustworthy before snapshot exists. **Observed impact cannot be conclusively established.** No real account data was intentionally touched during this closure run.

`TestSandboxGuard` now requires a GUID-N child of `%TEMP%\SpeedMeterPro.Tests`, an exact sentinel, contained absolute children, and reparse checks. Fixture recursive cleanup uses `TestDeleteGuard`; App smoke and DevelopmentTest updater modes route data, settings, logs, crashes and the instance lock into that validated root. The production installer validates a dedicated product leaf, owned marker, exact executable shutdown and canonical current-user purge; only internal tests can supply a guarded sandbox data directory. Legacy generated ZIP install/uninstall scripts were removed. These are source and fixture safeguards, not proof that all deletion races are closed.

Independent Security/Privacy review in `docs/reviews/V1-CONS-SECURITY-002.md` remains **CHANGES REQUESTED**. Its remaining material concern is the deferred `cmd` batch deletion and purge validation-to-delete race, including failures for legitimate profile paths with CMD metacharacters. The package-output delete inventory also needs reviewer closure. Director fixes to canonical process matching occurred after that review and have not been independently accepted. Do not run a production-profile purge or mark AC-S07 complete until a safe implementation and review are recorded.

Source inspection found distinct normal Production trust (fixed HTTPS GitHub manifest and embedded key) and compile-time-only DevelopmentTest trust (`SPEEDMETER_UPDATE_LAB`) restricted to a sentinelled root and same loopback origin. Settings cannot select DevelopmentTest. The live test used a signed DevelopmentTest manifest and test-signed package served from `127.0.0.1:8765`; it does not establish a live public GitHub update channel. Manifest signature, package SHA-256/size, and WinVerifyTrust publisher checks were exercised before installer launch. Tampered-signature, hash, publisher, downgrade and failed-stage recovery have executable fixtures; a full native consumer recovery drill remains pending.

The first live one-click attempt fetched and verified RC.3 but left RC.2 installed. The updater passed a trailing separator in `-Dir`; exact reproduction returned Setup exit 1, whereas the normalized path returned 0. The updater and installer were fixed, with a trailing-separator fixture. A subsequent live one-click drill succeeded. The final-source repetition used an RC.2 lab app to fetch the signed manifest and RC.3 Setup, shut down the old process, installed `1.0.0-rc.3+1badfde9e3e79770195b63e843e506e79a6ebd3f`, and relaunched one app process. The server log shows both GETs. UI Automation observed `Active · Scope: Primary candidate: Wi-Fi`; the floating widget opened. Lab snapshots are `artifacts/lab/before-final.json` and `artifacts/lab/after-final.json` (local ignored artifacts).

The final repetition preserved **all 1,110** pre-upgrade interval IDs and exact RX/TX counters; 1,219 intervals existed afterwards. SQLite schema stayed 3 and `PRAGMA integrity_check` returned `ok`. Collection sessions increased 3→5. The only changed settings fields were update check timestamps; selected Light theme, Detailed widget, opacity 0.72, first-run completion, update opt-in, disabled connection/public-IP requests and quota rule stayed intact. Quota threshold and alert event tables both contained zero rows before and after, so event preservation was **not** demonstrated. This observed sandbox drill is not a production-trust or public-channel update.

## Interactive install, uninstall and other consumer paths

The final RC.3 graphical Setup was driven through install location/options, progress and completion; installation succeeded. The default Launch option was switched off at Finish to avoid starting a production-mode app against real current-account data. A graphical keep-data uninstall showed purge unchecked by default; Cancel left the install intact. A second graphical keep-data uninstall completed and its target directory was observed removed after Finish. One earlier uninstall check found the directory still present at 15 seconds before guarded cleanup, so deferred completion timing is not characterized. Installed Apps registration was not exercised: custom sandbox installs intentionally avoid the real HKCU registration, and canonical install would alter an existing real profile. Native purge and native reinstall of a retained data directory remain unverified.

Executable crash/report fixtures pass, but controlled packaged crash capture, next-launch UX, diagnostic export and GitHub issue action were not observed end to end. Zero-external-traffic is covered by a fixture invariant, not packet/process observation. Update consent was observed in seeded opt-in settings and explicit `Check for updates`/`Update now` actions; no passive first-run network capture was made. Native keyboard, Narrator, High Contrast, 150% DPI and text scaling review could not be completed because the accessibility helper timed out; see `docs/reviews/V1-CONS-ACCESSIBILITY-002.md` (**NOT VERIFIED**).
